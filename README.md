# ASDL application

The project runs as a Docker Compose stack: React/Vite frontend, FastAPI backend, and MySQL database. Install Docker Desktop (or Docker Engine with the Compose plugin) on the machine, then start the stack from this directory.

## Start the application

From a terminal opened in the project directory, run the same command on Windows, macOS, or Linux:

```sh
docker compose up
```

Compose builds the frontend and backend images from their Dockerfiles as part of startup. It supplies development defaults, so copying `.env.example` is optional. Create a `.env` file from that example only when you want to customize the settings.

Open the frontend at `http://localhost:8080`. FastAPI is also available at `http://localhost:8000`; its Swagger UI is at `http://localhost:8000/docs` and ReDoc at `http://localhost:8000/redoc`. The frontend proxies API requests through the same origin.

Stop the services with `docker compose down`. MySQL data remains in the `mysql-data` Docker volume. To remove the database and all its data, run `docker compose down --volumes`.

Compose waits for MySQL to become healthy before starting the backend. The database connection is supplied inside the Docker network; no local Python, Node.js, or MySQL installation is needed.

## Database migrations

Once the ERD-based SQLAlchemy models and first migration are in place, apply migrations with:

```powershell
docker compose exec backend alembic upgrade head
```

Create a migration after changing models with:

```powershell
docker compose exec backend alembic revision --autogenerate -m "describe schema change"
```

Review autogenerated migrations before applying them. Environment values can be changed in `.env` before starting Compose.
